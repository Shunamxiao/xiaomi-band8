# 连接链路梳理与“任意手环”可行性（2026-10-25）

> 结论先行：
> 1. 不依赖手机可行。已实测 PC（Intel 蓝牙）直接连接手环并完成认证。
> 2. 支持任意小米手环 8 可行，但前提是手环处于“未绑定”状态；密钥来自手环本地的绑定握手，不需要小米账号或云端。
> 3. 已绑定的手环不能强行接管，这是设备的安全设计；必须先由原绑定方解绑或手环恢复出厂。

## 一、当前链路（分层）

    ┌──────────────────────────────────────────────┐
    │ 业务层  Command{type, subtype, payload}       │
    │  2/1 电量  2/18 查找  7/0 通知  4/4 表盘 …    │
    ├──────────────────────────────────────────────┤
    │ 会话层  AES-CCM(4B MAC) + 递增 nonce          │
    │  发送 nonce = appIV(4) + 0(4) + index(u32 LE) │
    │  接收 nonce = deviceIV(4) + 0(8)              │
    ├──────────────────────────────────────────────┤
    │ 认证层  cmd26 / cmd27                         │
    │  HKDF(encrypt_key, appRand||devRand,          │
    │       "miwear-auth", 64B)                      │
    │  → deviceKey / appKey / deviceIV / appIV       │
    ├──────────────────────────────────────────────┤
    │ 帧层  [seq u16][type][dataType][body]          │
    │  每帧回 ACK 00 00 03 00                        │
    ├──────────────────────────────────────────────┤
    │ 传输层  BLE GATT                              │
    │  服务 0xFE95  写 0x0052  通知 0x0051           │
    └──────────────────────────────────────────────┘

已实测（PC，2026-10-25）：

- 扫描：PC BLE 栈可正常发现小米生态设备；
- 直连：使用已知 MAC 直接连接，不经过手机；
- 认证：HKDF + HMAC 校验通过，会话密钥建立成功；
- 说明：PC 端只需要 BLE 适配器，不依赖 Android 手机。

## 二、密钥从哪里来（关键）

encrypt_key 是绑定阶段产生的 16 字节长期密钥，不是固定值，也不是从 MAC/SN 推导。

官方实现（com.xiaomi.device.binder.LocalWearBinderV2）显示绑定是纯本地流程：

1. App 生成 P-256（secp256r1）密钥对；
2. 发送 Command{type=1, subtype=18}，payload：
   ua0{ 17: sb0{ 1: appDeviceId, 2: appPublicKey(64B) } }
3. 手环返回 ua0{ 18: yb0{ 1,2,3 } }（设备公钥 / 签名 / 设备随机数）；
4. App 计算 ECDH 共享密钥，校验签名；
5. App 生成 16B appRandom；
6. 派生：

       derived = HKDF-SHA256(
           ikm  = sharedKey,
           salt = appRandom || devRandom,
           info = "miwear-bind",
           len  = 64
       )

   其中 derived[40:56] 就是 encrypt_key（官方代码把它同时写入 token 与 encryptKey）。
7. 发送 Command{type=1, subtype=19} 确认，再发 subtype=25 上报绑定结果；
8. 绑定完成，后续用 encrypt_key 走 cmd26/27 认证。

关键事实：

- DualCoreDeviceBinder.checkLogin() 返回 false，bindWithUserId() 返回 false；
- 绑定不要求登录小米账号；
- appDeviceId = MD5(phoneId + MAC大写 + userId)，只是标识，不参与密钥。

## 三、能否连接任意手环 8

| 手环状态 | 能否连接 | 说明 |
|----------|----------|------|
| 全新 / 未绑定 | 可以 | 用本地绑定流程取得 encrypt_key，随后完全自研控制 |
| 已由官方 App 绑定 | 需先解绑 | 手环只认已绑定的密钥；强行绑定会被拒绝 |
| 恢复出厂后 | 可以 | 等同于未绑定 |
| 他人手环 | 不可以 | 无法绕过绑定校验，也不应尝试 |

因此“任意手环”的准确表述是：任意一台处于可绑定状态的小米手环 8。

## 四、三种落地架构

### 方案 A：PC 直连（推荐当前阶段）
- 运行环境：Windows/Linux + BLE 适配器；
- 优点：无手机依赖、调试方便、可接 MCP/服务端；
- 已验证：认证链路；
- 待补：本地绑定（需要一台未绑定手环做真机验证）。

### 方案 B：Android APK 直连（已有）
- 优点：随身、可监听通知；
- 依赖：每台手环的 encrypt_key；
- 与方案 A 共用同一套协议实现。

### 方案 C：手机中继（现状，不推荐长期）
- 手机连手环，PC 通过 HTTP 下发；
- 优点：无需改绑定；
- 缺点：多一跳、依赖手机、维护成本高。

## 五、实现建议（按优先级）

1. 抽出密钥库：{mac, model, encrypt_key, app_device_id, bound_at} 存 JSON/SQLite；
2. PC 客户端参数化：MAC 与密钥从密钥库读取，不再硬编码；
3. 实现本地绑定（band8/bind.py）：
   - P-256 密钥对；
   - 1/18 → 1/19 → 1/25；
   - 保存 derived[40:56]；
4. 用一台未绑定手环验证：确认 yb0 三个字段的顺序与绑定确认行为；
5. 补业务命令：电量、通知、查找、闹钟、表盘；
6. 最后再考虑把 PC 客户端暴露为 MCP 工具。

## 六、风险与边界

- 绑定会改变手环的归属密钥；在已使用的手环上测试可能导致需要恢复出厂，务必用备用设备；
- 不同固件版本的绑定字段可能变化，需要按固件版本做兼容；
- 不要把 encrypt_key 提交到仓库或发到公网；
- 本项目仅用于自有设备的研究与自用，不应用于接管他人设备。
